# LIVE:GUARD 커뮤니티 정책

문서 ID CP · 정책 세트 0.3-draft · 팀 작성·검토용 · 적용: 자체 시연 채널과 가상 이용자

## CP-1.1 정상 반응·내용 비판

“무대 미쳤다”, “개잘한다” 등 긍정 과장과 “진행이 느리다” 같은 내용 비판은 맥락을 확인해 정상 예외로 둔다. 단어 일치만으로 인격 공격이라고 결론 내리지 않는다. 반어·표적 조롱 여부가 불명확하면 필요한 대화를 조회한다.

정상 판단은 NO_VIOLATION이다. PUBLIC이면 유지, HELD면 서버 검증 후 RELEASE_HELD 자동 실행. 이미 HIDDEN이면 최초 조사 정상 분기로 풀지 않고 원조치 재검토를 거친다.

## CP-1.2 인용·주의·설명 예외

“방송 접으라는 말은 하지 마세요”처럼 공격을 말리거나 사례를 설명한 문장은 실제 공격과 구분한다. 따옴표·장난이라는 말만으로 예외를 인정하지 않는다. 앞뒤 문맥을 확보하지 못하면 NEEDS_REVIEW다.

## CP-2.1 공격 표현·단발 욕설의 조사

욕설·비하 사전 매칭과 명시적 대상+공격 표현은 REVIEW 후보이며 공개 유지 후 조사한다. 노골적 욕설은 부적절한 표현 신호지만 최신 MVP의 독립 PROFANITY 제재표는 없다. 단발 욕설을 근거로 반복 괴롭힘을 확정하거나 자동 제한을 요청하지 않는다.

부적절한 단일 공격은 자동 요건 부족을 표시해 NEEDS_REVIEW·예외 검토로 보낼 수 있다. NO_VIOLATION이라고 억지로 재분류하거나 v0.2 장기 제재표를 적용하지 않는다. 반복 여부·대상·인용 문맥은 실제 message_id로 확인한다.

## CP-3.2 반복 괴롭힘

**기획서 기본안:** 같은 작성자가 같은 채널에서 최근 5분 내 같은 대상에게 별개의 공격 발언을 3건 이상 한 사실을 맥락으로 확인한다.

- 대상은 답글·멘션·출연자 정보·명시적 문맥으로 확인한다. 모델이 신원을 추정하지 않는다.
- 일반 비판·긍정 반응·제지 인용·전송 재시도를 공격 건수에서 제외한다.
- “너는 왜 맨날 그러냐. 방송 접어라” 한 줄만으로 반복을 확정하지 않는다.
- 과거 30일 제재 횟수는 현재 3건/5분 근거를 대신하지 않는다. 취소 이력을 함께 확인한다.
- VIOLATION에는 대상·별개 발언 3개 이상의 message_id·수신 시각·정책 버전을 남긴다. 정책 조건을 만족하면 메시지별 HIDE와 해당 채널 TIMEOUT 300초를 자동 계획으로 요청한다.
- 같은 근거 재처리로 새 제한을 추가하거나 기존 만료를 연장하지 않는다.

## CP-4.1 도배

같은 사용자·채널에서 10초 내 정규화 동일 문장 3회 이상이면 세 번째부터 임시 가림한다. 공백 축약·유니코드 정규화·동일 문자 반복 축소로 비교하고 의미 유사도는 쓰지 않는다. 원문·정규화 결과·규칙 버전을 구분한다.

- 같은 clientMessageId 재전송은 한 건이다. 여러 사람의 같은 응원은 합치지 않는다.
- 최초 3회 판정에 사용한 첫 메시지 t0부터 [t0,t0+10초)로 묶고 처음 두 메시지는 증거로 연결한다. 창 종료 시 최초 조사 1회.
- 정상 반복 맥락과 재전송을 제외해 VIOLATION을 확인하면 세 번째 이후 중복 message_id별 HIDE를 요청한다. 도배만으로 TIMEOUT을 추가하지 않는다.
- 이미 제재 근거로 사용한 메시지를 다른 사건에서 재사용해 추가 제한하지 않는다.

## CP-5.1 사칭·외부 유도

SP-2.1을 적용한다. 외부 링크·공식 단어만으로 확정하지 않고 실제 역할·등록 주소·이벤트·계정정보 요구를 확인한다. 다른 유형의 혐오·성희롱·개인정보 유출을 별도 자동 제재로 확대하지 않는다.

## CP-6.1 판단의 한계와 기록

판단은 VIOLATION/NO_VIOLATION/NEEDS_REVIEW다. 필터 태그와 최종 판단, 자동 실행 자격을 별도로 저장한다. 조사 데이터가 현재 정책 조건을 충족하지 않으면 검색 조항이 있어도 신규 확정 조치를 만들지 않는다.

출처는 기존 기획서의 공개 정책 참고 자료이며 실제 적용 기준은 본 자체 정책이다. 이 문서는 0.3-draft, 자동 규칙 설정과 버전을 맞춘 뒤 색인한다. 정책 문서 준비는 실행 검증을 뜻하지 않는다.
