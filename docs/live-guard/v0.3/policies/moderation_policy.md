# LIVE:GUARD 자동 조치 정책

문서 ID MP · 정책 세트 0.3-draft · 상태: 기획서 기본안 반영·Day 0 동결 필요

## MP-1.1 자동 실행 요건

최초 조치는 운영자 사전 승인 없이 실행한다. 다음이 모두 충족돼야 한다.

1. VIOLATION과 실제 조회된 증거 message_id.
2. 해당 사실을 뒷받침하는 정책 조항 1개 이상과 유효한 정책 버전.
3. 자동 조치표의 유형·조건·대상·기간 일치.
4. 최신 사건·증거·대상 버전, 채널·사용자 범위.
5. 동일 근거 중복 실행·활성 제한 연장 방지 검증.

모델의 요청은 제안이다. Backend가 저장한 planId·actionId·ActionCommand가 실행 기준이다. 코드 실행 노드만 변경 도구를 호출하며 조사 모델에는 조회·검색 도구만 노출한다.

## MP-2.1 자동 조치표

| 유형·조건 | 메시지 조치 | 사용자 조치 | 과거 위반 0/1/2건 이상 |
|---|---|---|---|
| CP-3.2 반복 괴롭힘 3건/5분 충족 | 해당 공격 메시지별 HIDE | 해당 채널 TIMEOUT 300초 | 모두 동일, 우선순위만 조정 |
| CP-4.1 도배 확정 | 세 번째 이후 중복 메시지별 HIDE | 없음 | 동일 |
| SP-2.1 사칭·외부 유도 위험 요건 | 해당 메시지별 HIDE | 없음 | 동일 |
| 정상 HELD | RELEASE_HELD | 없음 | 이력과 무관 |
| 단일 공격·근거 부족 | 신규 확정 자동 조치 없음 | 없음 | 이력으로 요건 대체 금지 |

**기간은 기획서의 팀 검토용 기본안이다. 상한은 300초이며 모델·관리자 수동 예외 경로도 넘을 수 없다.** 이전 10분·24시간·7일 가중표를 사용하지 않는다. 강한 제재 설정·영구 제한은 MVP 밖이다.

같은 채널의 유효 제한 중에는 새 TIMEOUT으로 만료를 갱신하지 않고 기존 조치와 연결한다. 재시도는 최초 성공 시 저장한 startedAt·expiresAt을 반환한다. 다른 채널에는 영향을 주지 않는다.

## MP-2.2 정상 해제와 확정 조치 취소

- RELEASE_HELD: 정상으로 확인된 해당 HELD 메시지만 PUBLIC으로 자동 변경.
- RESTORE_MESSAGE: 운영자 OVERTURN 결정에 연결된 원 HIDE 조치의 메시지 복구. 원조치·결정 ID 검증.
- REVOKE_TIMEOUT: 운영자 OVERTURN 결정에 연결된 특정 원 TIMEOUT만 취소.
- HIDDEN을 NO_VIOLATION 분기만으로 PUBLIC으로 바꾸지 않는다. 취소는 MM 재검토 절차를 따른다.
- 이의제기 접수·조사·UPHOLD는 제한을 연장하거나 자동 해제하지 않는다.

## MP-3.1 위반 이력

적용이 확인된 사건별 위반 기록 1건으로 센다. 메시지별 HIDE 여러 건과 TIMEOUT, 재시도·재조사·보고는 새 위반이 아니다. 동일 증거를 재사용해 추가 제재하지 않는다.

취소된 위반은 가중 이력에서 제외하고 원래 이력·취소 이력은 보존한다. 부분 취소 사건의 유효성을 원조치와 연결해 표시한다. 동일 유형 30일 이력 구분은 조회 설명용이며 제한 시간 가중에 사용하지 않는다. 현재 정책의 자동 기간은 과거 횟수와 무관하다.

## MP-4.1 조치 ID와 멱등성

| 논리 조치 | 유일 범위 |
|---|---|
| HIDE | caseId + HIDE + messageId |
| TIMEOUT | caseId + TIMEOUT + channelId:userId |
| RELEASE_HELD | caseId + RELEASE_HELD + messageId |
| RESTORE_MESSAGE·REVOKE_TIMEOUT | reviewDecisionId + type + originalActionId |

Backend가 actionId를 발급하고 키는 `action:{action_id}`로 저장한다. 같은 키·같은 요청은 **실제 저장 상태·결과**를 반환한다. 같은 키·다른 payload는 409 IDEMPOTENCY_CONFLICT다. 실패한 기록을 성공으로 응답하지 않는다.

계획의 조치별 버전을 추적한다. 같은 계획의 앞 조치가 만든 정상 상태 변경과 외부 증거 변경을 구분하며, 실제 새로운 증거로 오래된 계획이면 STALE_VERSION으로 차단한다. 메시지 HIDE는 개별 ID로 기록하고 성공·실패를 개별 반환한다.

## MP-4.2 실행 결과·UNKNOWN

| status | applied | 의미·처리 |
|---|---|---|
| PENDING/RUNNING | 확정 전 | 진행 중, 중복 실행 금지 |
| SUCCEEDED | true | 실제 반영 확인 |
| FAILED | false | 미반영이 확인된 최종 실패 |
| UNKNOWN | null | 반영 여부 불명, 같은 actionId 조회 우선 |

네트워크 시간 초과·404만으로 미반영을 확정하지 않는다. 처리 중 동일 요청이 없는지 포함해 서버가 미반영을 판정한 일시 오류만 같은 키로 재시도한다. 적용됐으면 성공 확정하고 재실행하지 않는다. 끝까지 확인 불가면 UNKNOWN 유지·운영자에게 보고한다.

HIDE 성공·TIMEOUT 실패는 부분 성공으로 표시한다. ACTIONED나 작업 SUCCEEDED만으로 모든 제재가 성공했다고 설명하지 않는다. 결과 조회·보고·복구 상태를 별도로 보존한다.

## MP-5.1 정책 원본·보고

버전 있는 단일 정책 설정이 실행 규칙 원본이다. 문서 조치표·Backend 기준표를 같은 설정으로 생성·대조하며 불일치 버전은 실행 차단한다. RAG의 조항·Resource·스냅샷도 같은 버전이다. 이 패키지에는 설정 생성기나 DB 기준표가 아직 없다.

업무 상태 변경·조치 결과·보고 outbox를 가능한 한 같은 트랜잭션에 저장한다. 알림 실패는 조치 실패가 아니다. 보고만 재시도하고 제재·만료를 다시 계산하지 않는다.
