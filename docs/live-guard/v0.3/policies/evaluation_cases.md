# LIVE:GUARD 평가 사례 v0.3

상태: **가상 사례·기대값 설계 / 데이터 시드·모델 호출·실행 평가 미수행**

## 1. 공통 조건·집계

총 30건: VIOLATION 15·NO_VIOLATION 10·NEEDS_REVIEW 5. 개발 20건(10/7/3), 최종 보류 10건(5/3/2)으로 나눈다. 아래 라벨은 명시한 fixture 문맥이 실제로 제공되는 조건이다. 임계값·기간은 기획서의 Day 0 동결 전 기본안이다.

채널 C1·C2, 사용자 U1·U2, 대상 출연자 T1을 사용한다. URL은 테스트 호스트이며 접속하지 않는다. 사전에는 긍정 과장·공격·인용 시나리오에 필요한 표현을 고정하고 Baseline과 같은 설정을 사용한다. 역할·공식 주소·이벤트 정보는 해당 조회 도구에서 제공한다.

반복 괴롭힘 fixture의 3건은 같은 작성자·채널·대상, 최근 5분 내 별개의 공격 메시지다. 같은 clientMessageId 재전송·단순 인용·내용 비판은 제외한다. 단일 공격은 자동 반복 요건 미충족으로 NEEDS_REVIEW에 둔다.

PASS는 Agent 미호출이므로 전체 채팅의 초기 분류 평가에 포함하고 최종 라벨을 기록한다. 조사 대상으로 골라낸 사례만으로 전체 채팅 탐지율이라고 발표하지 않는다. 아래는 의도된 사례 구성으로 실제 도착 순서·수집 창·정규화 값을 seed에 고정해야 한다.

## 5. 기록·지표

각 판단 사례에 정책·모델·프롬프트·사전 버전, 고정 입력·시간·도착 순서·필수 도구, 기대·관찰 판단, messageId·policyId, action plan·실제 반영·원문 공개 범위, 호출 수·토큰·trace를 기록한다. 시스템 시험은 요청·서버 응답·DB 상태·재시작 증거를 연결한다.

전체 채팅 100~200건의 초기 탐지·정상 임시 가림률과 위 30건의 판단·근거·조치 품질은 분모를 나눠 보고한다. NEEDS_REVIEW와 UNKNOWN을 제외해 성공률을 높이지 말고 건수·비율·후속 결과를 따로 표시한다.

시간은 저장·초기 가림·수집 창·큐·조사·실제 변경·후보고·사람 대기로 나눈다. 부하는 초당 1개 및 초당 10개·10초부터 실제 수행한 조건만 보고한다. 측정 전 칸에는 예정으로 표시한다. 문서 구조 확인은 모델·플랫폼 실행 성능을 증명하지 않는다.
