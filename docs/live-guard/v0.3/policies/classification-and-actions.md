## 3. 범위·필터·공개 상태

LIVE:GUARD는 플랫폼이 도입하고 시청자가 조치 사유·이의제기를 이용하는 B2B2C다. 자체 시연 채널 1개와 접근 제어 검증 채널 1개, 가상 계정·데이터를 사용한다. 실제 플랫폼 연동·영구 정지·영상/음성 분석·사이트 방문 검사는 제외한다.

| 1차 결과 | 기획서 조건 | 상태 | 후속 |
|---|---|---|---|
| PASS | 다른 조건 없음 | PUBLIC | 기본 미분석, 이후 신고 가능 |
| REVIEW | 공격·비하 사전 또는 대상 지칭+공격 표현 | PUBLIC | 맥락 조사 |
| HOLD | 공식 자칭+로그인/인증 요구+비공식 URL | HELD | 1초 내 조사 요청 |
| FLOOD | 같은 사용자·채널, 10초 내 동일 정규화 문장 3회 | 세 번째부터 HELD | 10초 묶음 조사 |

대표 순서는 HOLD>FLOOD>REVIEW>PASS이며 모든 매칭 태그를 보존한다. 전화번호·계좌 패턴 단독은 HOLD나 독립 제재 조건이 아니다. URL 하나만으로도 HOLD·피싱 확정하지 않는다.

공백 축약·유니코드 정규화·동일 문자 반복 축소 후 문자열 비교로 시작한다. 의미 유사도는 제외한다. 같은 clientMessageId·같은 내용은 기존 응답, 같은 ID·다른 내용은 충돌이며 전송·도배 수를 늘리지 않는다.

| 메시지 상태 | 작성자 | 다른 시청자 | 담당 운영자 |
|---|---|---|---|
| PUBLIC | 표시 | 표시 | 표시 |
| HELD | 원문·검토 상태 | 미전달·이력 제외 | 원문·보류 사유 |
| HIDDEN | 원문·조치 사유 | 미전달·이력 제외 | 원문·정책·실행 결과 |

SSE 최초 전송·재연결·이력 API 모두 같은 범위를 검사한다. HELD 원문을 일반 CHAT으로 먼저 보낸 뒤 지우지 않는다. 이미 공개된 메시지는 숨김 이벤트로 화면에서 제거할 수 있지만 전달된 원문까지 회수한 것은 아니다.

## 4. 사건 묶음·증거 버전

| 경로 | 기준 |
|---|---|
| REVIEW | 첫 후보부터 3초 고정 수집, 종료 시 1회 조사 |
| HOLD | 감지부터 1초 이내 조사 요청, 후속은 연결·즉시 가림 |
| FLOOD | 최초 3회 판정의 첫 메시지 시각 t0부터 [t0,t0+10초), 처음 두 메시지도 증거 연결, 종료 시 1회 조사 |
| 분석 전 승격 | REVIEW→FLOOD는 도배 마감으로 변경, REVIEW→HOLD는 감지 후 1초 이내 요청 |
| 분석 중 추가 | evidence_version·case_version 갱신, dirty=true. 기존 조사 스냅샷은 유지 |
| 오래된 계획 | 실행 전 expectedCaseVersion 불일치면 거부, 새 스냅샷 후속 분석 최대 1회 |
| 계속 변경 | 추가 확정 조치 없이 NEEDS_REVIEW·예외 검토 |
| 종료 후 후보 | 새 사건. 기존 조치·중복 증거·유효 제한 검사 |

사용자·채널을 넘겨 합치지 않는다. 같은 사건의 정상 메시지·위반 메시지는 ID별로 구분한다. 혼합 사건의 대표 필터가 HOLD라고 전부 숨기지 않는다. 최초 두 도배 메시지는 증거로 연결되더라도, 현재 기본 조치 대상은 세 번째 이후 중복 메시지다.

시연: 같은 문장을 t0부터 0.9초 간격 10회 전송하면 한 10초 창에 들어가 사건 1건·최초 조사 1건이다. 10초 이후 트래픽까지 무조건 같은 사건으로 묶지 않는다. 사용자·채널별 동시 수신을 직렬화해 중복 사건·연결을 방지한다.

## 5. 판단과 자동 실행

| 판단·조건 | 처리 |
|---|---|
| NO_VIOLATION + PUBLIC | 공개 유지·기록 |
| NO_VIOLATION + HELD | 검증된 RELEASE_HELD 자동 실행·결과 확인 |
| NO_VIOLATION + 기존 HIDDEN | 최초 정상 분기로 복원 금지. 원조치 재검토·취소 결정 필요 |
| VIOLATION + 자동 요건 충족 | 서버가 action plan 발급·변경 도구 자동 호출·조회 |
| NEEDS_REVIEW | 신규 확정 제재 없음, 기존 가림 유지·검토 사유 표시 |
| 정책/권한/증거 버전 불일치 | 실행 차단·예외 또는 후속 분석 |
| 실행 결과 불명 | UNKNOWN·조치 ID로 실제 상태 확인 |

VIOLATION만으로 실행하지 않는다. 실제 조회한 메시지 ID, 유효 정책 조항, 같은 버전의 조치표, 최신 사건·대상 버전, 허용된 채널·기간이 모두 필요하다. 모델의 requestedActions는 권한이 아니다. 변경 도구는 조사 모델에게 노출하지 않고 코드가 서버 발급 ActionCommand만 실행한다.

반복 괴롭힘의 기본안은 **최근 5분 내 같은 대상에 대한 별개의 공격 발언 3건 이상** 확인이다. 과거 30일 제재 수만으로 현재 반복 요건을 대신하지 않는다. 단일 공격·일반 욕설은 반복 제한 요건을 충족하지 않는다.

## 6. 조치·이력·결과·보고

| 대상 | 실행 |
|---|---|
| 반복 괴롭힘 요건 충족 | 해당 공격 메시지별 HIDE + 해당 채널 TIMEOUT 300초 |
| 도배 확정 | 세 번째 이후 중복 메시지별 HIDE |
| 사칭·외부 유도 요건 충족 | 해당 메시지별 HIDE; 자동 TIMEOUT 추가 없음 |
| 정상 임시 가림 | RELEASE_HELD |
| 이의제기 취소 | 원조치별 RESTORE_MESSAGE 또는 REVOKE_TIMEOUT |

30일 유효 위반 수는 맥락·검토 우선순위이며 기간을 늘리는 값이 아니다. 메시지 수·HIDE/TIMEOUT 수·재시도·재조사를 별도 위반으로 세지 않는다. 취소된 위반은 가중 이력에서 제외한다. 여러 메시지 숨김과 제한 중 일부가 취소된 사건의 유형별 유효 기록 판정은 원조치 연결로 설명할 수 있게 관리한다.

기존 같은 채널 제한이 유효하면 새 TIMEOUT으로 만료를 연장하지 않고 기존 조치에 연결해 보고한다. 다른 채널은 제한하지 않는다. 수동 예외 처리도 5분 상한·정책 조건을 넘지 못한다.

실행은 PENDING/RUNNING/SUCCEEDED/FAILED/UNKNOWN으로 구분한다. applied는 확인 true, 미반영 확인 false, 불명 null이다. UNKNOWN은 먼저 get_action_status로 확인한다. 오류·404 하나만으로 미반영이라고 간주하지 않는다.

조치 성공과 보고 성공은 별개다. HIDE 성공·TIMEOUT 실패는 각각 기록하며 한 성공으로 모두 완료라 표시하지 않는다. 통지 실패는 NOTIFY만 재시도하며 제재를 다시 실행하지 않는다. action_id별 키·입력·최초 종료 시각을 유지한다.

## 7. 이의제기와 사람 개입

시청자는 본인 조치 1건의 actionId에 이유를 제출한다. 같은 사건의 HIDE와 TIMEOUT도 각각 이의제기·유지·취소한다. 접수만으로 해제·연장하지 않는다.

> 접수 → 원조치·근거·추가 문맥 조사 → REVIEW_PENDING·체크포인트 → MODERATOR 결정 → 같은 재검토 thread 재개 → 권한·최신 버전 확인 → 유지 또는 해당 조치 취소·복구 → 결과 조회·통지

결정은 UPHOLD/OVERTURN, 저장 상태는 UPHELD/OVERTURNED다. OVERTURNED가 복구 성공을 뜻하지 않으며 복구 ActionResult를 별도 표시한다. 만료된 제한의 잘못된 이력도 취소할 수 있고 다른 유효 제한까지 해제하지 않는다.

최초 조사 thread는 `case:{case_id}:analysis:{revision}`, 이의제기는 `case:{case_id}:appeal:{appeal_id}`다. task_id·case_id·thread_id·trace_id·action_id·decision_id를 구분한다. 재시작·재개 시 카운터를 초기화하지 않는다.

## 8. 정책·인증·실행 통제

- 자동 규칙의 단일 버전 설정에서 문서 조치표와 Backend 기준표를 생성·대조한다. 불일치면 실행 차단. 이번 문서 작성은 이 생성기의 구현이 아니다.
- RAG는 자체 정책만 색인하고 실제 대화·외부 플랫폼 기간표를 섞지 않는다. pgvector 사용, 임베딩 모델·차원·색인 버전 일치.
- Resource는 `policy://{version}/{documentId}/{sectionId}`. 판단 당시 원문·버전을 스냅샷으로 보존한다.
- 세션 쿠키·같은 출처 프록시·CSRF·역할·채널 권한을 적용한다. 내부 서비스 토큰을 일반 사용자 승인으로 취급하지 않는다.
- 전화·계좌·이메일·URL 경로·닉네임은 모델/도구 결과/trace에서 마스킹한다. 개인정보 마스킹과 독립 개인정보 제재는 구분한다.
- 초기 실행 후 추가 재시도 2회는 SDK/Graph/Worker 공유 예산. NOTIFY는 별도 예산. UNKNOWN은 조회부터 한다.
- 자동 조치와 사후 HITL은 교재의 모든 변경 전 승인 원칙과 같다고 주장하지 않는다. 사용자 선택에 따른 차이를 평가 대응에 표시한다.

**미정 세부사항:** 단일 욕설만의 자동 숨김은 세 유형 표에 없으므로 신규 실행 근거로 사용하지 않는다. 같은 유형 30일 기록의 상세 분해는 이력 표시를 위한 보완안이며, 자동 제한 가중표를 복원하지 않는다. 현 시점의 어떤 초안도 점수·정확도·운영 효과를 보장하지 않는다.
